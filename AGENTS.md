# Laylah development workflow

- GitHub `shoaib1121/Laylah` is authoritative. Inspect `git status` and preserve existing work before starting. Fetch the current GitHub default branch (currently `main`); create a descriptive feature branch from its latest remote commit for each task. Never reset away user work or force-push.
- Read PROJECT_CONTEXT.md and the relevant architecture/security documentation before editing. Preserve the React/Vite, Express, PostgreSQL design and security-learning goals. Do not change application behavior during tooling-only tasks.
- Install with `npm ci` separately in frontend and backend. Run frontend lint/build and existing tests (`npm run test --if-present`), backend `npm test`, both lockfile dependency audits (`npm audit --package-lock-only --audit-level=high`), and `git diff --check`. Report failures and missing coverage honestly. No production deployment is configured or authorized.
- Update DEVELOPMENT_LOG.md with completed work, current status, pending work, known issues, validation, and security findings. Update PROJECT_CONTEXT.md for major handoff/decision changes, ARCHITECTURE.md only for actual architecture changes, and SECURITY.md/README.md when relevant. Avoid duplicate status files.
- Never stage real .env files, credentials, tokens, passwords, or private keys. `.env.example` must contain placeholders only. Inspect staged paths and diffs for secrets before committing; never print secret files. Do not automatically apply major dependency upgrades.
- Commit explicitly selected task files with meaningful messages, push the feature branch normally, and open a PR to the default branch with a change summary and test results. Never merge or enable automatic merging without the owner's explicit approval.
- End each task with repository, branch, latest commit SHA, PR URL, CI status, changed files, uncommitted changes, and manual actions/blockers. Distinguish local checks from observed GitHub Actions results.
- GitHub-connected ChatGPT reads committed remote state; it does not inherit Codex's live workspace or uncommitted edits. Ask it to inspect the latest requested branch and project docs rather than relying on old conversations.
